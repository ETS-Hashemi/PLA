# Paper (Overleaf project)

This folder is a self-contained Overleaf project whose main document is a
**scientific journal manuscript** in Elsevier's `elsarticle` class — the
class used by the target journals in `research/GAP_STATEMENT.md`
(*Knowledge-Based Systems*, *Expert Systems with Applications*,
*Information Sciences*).

| File | What it is |
|---|---|
| `main.tex` | **Journal manuscript** root (`elsarticle`) — frontmatter, sections via `sections/*.tex`, CRediT / declaration-of-interest / data-availability statements, numbered natbib references |
| `sections/` | One file per section (introduction … conclusion, appendices) |
| `figures/` | `overview.tex` (TikZ system figure) + data figures (`fig_*.pdf`) generated by `scripts/make_figures.py` |
| `references.bib` | BibTeX for every citation (32 entries, all cited) |
| `highlights.tex` | Elsevier Highlights, standalone one-pager (3–5 bullets, ≤85 chars each — enforced by eye, checked in review) |
| `cover_letter.tex` | Submission cover letter, standalone one-pager |
| `workshop.tex` | Secondary: self-contained 4–6 page workshop/tool-track cut (page-gated in CI) |
| `paper_draft.md` | Markdown working draft; superseded by `main.tex` for prose, kept for the claim-provenance table |
| `INTERNAL_REVIEW.md` | Adversarial pre-submission referee rounds and their dispositions |

## Compile

```bash
cd paper
pdflatex main && bibtex main && pdflatex main && pdflatex main   # journal manuscript
pdflatex workshop && pdflatex workshop                            # workshop cut
pdflatex highlights && pdflatex cover_letter                      # submission one-pagers
```

Requires `elsarticle` (TeX Live: `texlive-publishers`) and TikZ
(`texlive-pictures`); Overleaf has both preinstalled.

## Packages: Overleaf + submission

```bash
bash scripts/build_paper_package.sh
```

builds everything and assembles two archives in `dist/` (gitignored):

- **`overleaf_package.zip`** — the LaTeX sources with `main.tex` at the
  zip root. Upload as-is to Overleaf (Menu → New Project → Upload
  Project) and set `main.tex` as the main document. The script verifies
  this zip by unpacking and compiling it in a clean directory — exactly
  what Overleaf does.
- **`submission_package.zip`** — the Elsevier submission set:
  `manuscript.pdf`, `highlights.pdf`, `cover_letter.pdf`, and
  `source.zip` (the same Overleaf tree).

CI runs the same script on every push and uploads both archives as the
`submission-packages` artifact (PDFs land in `papers`).

## Class options (`main.tex`, first line)

- `[review,12pt]` — line-numbered submission layout: what you submit.
- `[preprint,12pt]` — single-spaced preprint (arXiv-style).
- `[final,3p,times]` — two-column journal-layout proof, for length checks.

Change `\journal{...}` to match the actual submission target.

## Editing rules

- Numbers in the results tables come from generated artifacts
  (`results/*.csv`). If the engine or experiments change, **regenerate
  and re-copy — never hand-edit** the values; Appendix B maps each claim
  to its verifying artifact, and `paper/INTERNAL_REVIEW.md` records the
  referee rounds that enforced this.
- Data figures regenerate with `python scripts/make_figures.py`
  (deterministic content; PDF bytes may differ across matplotlib
  versions).

## Before you actually submit (author checklist)

- Fill the funding/acknowledgements comment near the end of `main.tex`
  (grants, scholarships, compute support — not inferable from the repo).
- Confirm the target journal and adjust `\journal{...}`, the cover
  letter's addressee, and keyword count limits if the venue differs.
- Make the repository public (the data-availability statement and cover
  letter point reviewers at it).
