\section{Learning context-conditioned weights}\label{sec:learning}

\subsection{Reduction to logistic regression}

The reduction is stated under an explicit restriction: a \emph{flat}
rule set, every head is the target $T$, no chaining, over
\emph{crisp} binary facts $c(x)\in\{0,1\}$ (an example is a set of
active propositions and active context variables). With graded
antecedents the $\min$ term of \eqref{eq:candidate} enters the score
nonlinearly and the correspondence below no longer holds; the learner
therefore trains exactly the model class the experiments deploy, and no
more. Under the
\texttt{logit} context mode \eqref{eq:logit} with \texttt{logit\_pool}
aggregation \eqref{eq:aggregators}, a fired rule contributes candidate
$\sigma(z_r)$ with
\begin{equation}
z_r \;=\; \logit(p_r) + \sum_{v\ \text{active}} w_r(v),
\end{equation}
and folding candidates through \texttt{logit\_pool} telescopes; with
the intercept $b$ the experiments use throughout, the learned score
is
\begin{equation}
\hat{y} \;=\; \sigma\Bigl(b + \sum_{r\ \text{fired}} z_r\Bigr).
\label{eq:lr}
\end{equation}
Equation~\eqref{eq:lr} is logistic regression whose features are rule
firings and rule--context interactions, with parameters $b$,
$\theta_r = \logit(p_r)$, and $w_r(v)$. The intercept is not an
extra-logical term: it maps onto the engine as a base-rate prior rule
(an always-true antecedent with confidence $\sigma(b)$) folded first
by logit pooling, and the interceptless variant is the special case
$b = 0$. Read as a statement about
expressivity, this is deliberately deflationary: context conditioning
adds nothing a fixed-weight system could not represent with
context-conjoined rules, the contribution is that the engine
exposes the interaction in the rule's own vocabulary, exports the fit
back exactly, and traces it. On this learned classification path,
$\hat{y}$ is a discriminative conditional-probability estimate for the
target, which is what licenses cross-entropy training and the
calibration metrics of Section~\ref{sec:evaluation}, even though the
engine defines no joint distribution over all propositions
(Section~\ref{sec:notprob}). The binary cross-entropy loss is
convex in the parameters, so every local minimum is global.
Convexity alone guarantees neither a unique minimizer nor convergence
at an arbitrary step size, and under complete separation the infimum
need not be attained at any finite parameter, so the implementation
earns descent by construction instead of by assumption: each
full-batch epoch is accepted only if the compiled loss does not
increase, otherwise the step is rolled back and the rate halved (a
backtracking guard, unit-tested against a deliberately oversized
step). For reference, the usual smoothness argument bounds the BCE
smoothness constant by $\bar{L} = \max_i \lVert x_i\rVert^2/4$, and
$\lVert x_i\rVert^2 \le 2R + 1$ when all $R$ rules fire with one
active context interaction each, plus the intercept; in our designs
$\bar{L} = 23/4$, so any constant step
$0 < \eta < 2/\bar{L} = 8/23 \approx 0.348$ provably decreases the
loss each epoch. Our runs use $\eta = 1.0$: above that conservative
bound, and covered by the guard, which never fired in any reported
run; every reported trajectory is therefore monotone by construction
and re-asserted per epoch by the test suite. Zero-rule examples mark
the one place the implementation deliberately steps outside
Eq.~\eqref{eq:lr}: the pure reduction with $b = 0$ scores an empty
fired set at $\sigma(0) = \tfrac12$, absurd on rare-event data, so the
interceptless configuration instead assigns a fixed out-of-model floor
($10^{-3}$, an implementation convention documented as such, not a
prediction of the model class) and excludes those examples from the
gradient. With the intercept --- the configuration every reported
experiment uses --- no convention is needed: Eq.~\eqref{eq:lr} itself
scores the empty set at $\sigma(b)$, and the example trains the
intercept alone, the base-rate anchoring whose necessity the next
paragraph demonstrates.

\paragraph{The intercept matters} The reduction makes one classical
requirement visible the hard way. On rare-positive data, rules that are
strong \emph{lifts} but weak absolute probabilities (precision far below
$0.5$) force every $\theta_r$ negative in the interceptless model
($b = 0$ in Eq.~\eqref{eq:lr}); an
example firing five such rules (typically the most suspicious one)
then receives the \emph{lowest} score, inverting the ranking. We
observed exactly this on the real credit-card data (fitted
$\theta_r \approx -2.5$; frauds concentrated at five fired rules; AUC
$0.076$). With the intercept of Eq.~\eqref{eq:lr} in place, $b$
absorbs the base rate
($\approx \logit(0.0017)$) and the $\theta_r$ become positive lifts,
restoring AUC to $0.9625$ (Section~\ref{sec:evaluation}). The
engine-side equivalence of $b$ as a base-rate prior rule is
unit-tested, and a deterministic regression test reproduces the
inversion and its repair.

\subsection{Fidelity to the engine, and weight recovery}

Two properties tie the learner to the system it serves. First, fitted
parameters export back into the engine (rule confidences
$\sigma(\theta_r)$, context weights $w_r$) and the engine's queries then
match the learner's predictions to $10^{-9}$, what is trained is
literally what is executed. Second, on data sampled from a known model
in this family ($n=3{,}000$; three seeds), the learner recovers the
planted rule weights within $0.09$ and the planted context weight within
$0.29$, with the optimizer converged to $\sim 10^{-15}$ loss deltas; the
tolerances absorb sampling error only, since data, seeds, and optimizer
are all deterministic.

The learner is implemented in pure Python, no numpy, torch, or
scikit-learn, preserving the engine's zero-dependency property; the
training loop compiles the fixed dataset once (fired rules and active
context per example), which keeps thousand-epoch full-batch fits fast at
these scales.
